# Snap Your Wall with Gemini (dev copy)

This folder is a separate copy of the configurator on its own branch, `snapwall-gemini`. Nothing here touches the
main configurator, v1–v7 or the live site until it's merged on purpose.

**Part A "detect"** (this work): from a wall photo, find each compliance document, name its **type** and cut out a
full-quality image of it. **Part B "tracking"** (separate software) takes that and checks it against the legal
database. Part A never reads dates or license numbers.

## Run it
1. In this folder, run `node tools/serve.js`. (In the Claude app the preview is called **snapwall-dev**, port 8001.)
2. Open **http://localhost:8001/detect/**: the lab page. Snap or upload a wall photo, check and fix the results,
   and see the exact data handed to Part B.
3. The configurator's own Snap Your Wall step uses Gemini too: **http://localhost:8001/v5/** → Snap your wall.

With no key, the lab runs in **demo mode**: "Try the example wall" shows a pre-made answer, and the configurator uses
the old built-in scanner.

## v8: the configurator with Snap your wall
v8 is v7 plus a **Snap your wall** box at the top of the Documents step (Build). Take or upload one wall photo (or "see an example"):
Gemini names each certificate, the board is sized to fit, and signs/tags/wallet cards are left off. Only v8 asks Gemini; v2 to v7 are
unchanged. v8 is generated by `node tools/make-versions.js` like the other versions. Open it at `/v8/` (the double-click file opens it).
On GitHub Pages v8 needs the Cloudflare Worker (the key can't live in a public page); until then it works on this computer only.

## The Cloudflare Worker (what lets v8 work on a phone and on GitHub Pages)
The Worker holds the Gemini key so it never sits in a public page. Double-click **Build Cloudflare Worker** (it builds `worker/worker.js` and
copies it to the clipboard). In Cloudflare: Workers & Pages > Create > Hello World > name it `cobo-detect` > Deploy > Edit code > paste > Deploy.
Then Settings > Variables and Secrets > add a **secret** named `GEMINI_API_KEY` (paste the key from `.gemini-key`).
Only these sites may call it: jcolli40.github.io, complianceboards.com and www.complianceboards.com (add more with a text variable `ALLOWED_ORIGINS`).
Optional daily cap: create a KV namespace, bind it to the Worker as `LIMITS`; the default is 300 photos a day (`DAILY_LIMIT` changes it).
After deploying, put the Worker's address in `WORKER_URL` at the top of `js/detect.js`. Rebuild the Worker (double-click again) whenever
`tools/detect-core.js`, `tools/worker-handler.js` or `data/cert-types.json` change, then paste it again.

## Add the Gemini key
1. Go to https://aistudio.google.com → **Get API key** → **Create API key**. Copy it.
2. In this folder, create a plain text file named exactly `.gemini-key` and paste the key in, alone on one line.
3. Restart the preview. The lab's top-right badge should say **Gemini ready**.

`.gemini-key` is never committed to git and never served to the browser. Don't paste the key into chat.
For real customers, use a **paid** key: on Google's free tier, photos may be used to improve their products.

## Real-world accuracy test (one wall photo)
1. Take straight-on photos of real walls with your phone, then drag them onto the lab page on your computer.
2. In step 3, fix every mistake: change wrong types, remove things that aren't certificates.
3. In step 4, count any certificate Gemini missed with **+**, name the photo, add notes (lighting, glass, distance),
   then **Save to test log**.
4. The log adds up every test: right first time, wrong type, not certificates, missed, and how many were flagged for
   a closer photo. It also shows how often each confidence level was right, which tells us whether "high" can be
   trusted without asking the customer. **Download test log (CSV)** to keep it. It's only stored in that browser.

Gemini also flags each certificate that would need a closer photo (glare, too small, blurry, cut off, something in
front). The close-up step itself is built after these tests show how often it's needed.

## Settings (optional)
- `GEMINI_MODEL`: default `gemini-3.6-flash` (about 5 s per photo; `gemini-3.8-flash` was as accurate on the example wall but took about 9 s). The lab page can switch model, thinking and photo detail per photo, and saves them in the test log.
- `GEMINI_THINKING`: `minimal` / `low` (default) / `medium` / `high`. Higher is slower but may label better.

## Files
- `data/cert-types.json`: the 27 types (names match Part B), with other names they go by and how to recognize
  them. Edit this to add or rename types. Gemini's instructions are built from it.
- `tools/gemini-detect.js`: the Gemini request (instructions + the exact JSON it must return).
- `tools/serve.js`: the preview server, plus `/api/detect`, which holds the key.
- `js/detect.js`: the browser side (send photo, cut-outs, the Part B handoff, the demo wall).
- `detect/index.html`: the lab page.
- `js/main.js`: `scanWall()` tries Gemini first and falls back to the old scanner.

## Before customers can use it
- Test on 10–20 real wall photos. Fix types in the lab, then tune `data/cert-types.json` from the mistakes.
- Move `/api/detect` to a Cloudflare Worker (the key lives there) and point `DETECT_URL` in `js/detect.js` at it.
- Add a privacy-policy line: wall photos are sent to Google Gemini to recognize documents and are not stored.
- Agree the handoff format (`cobo-detect/1`) and type codes with whoever builds Part B.
